# Marginly / Locken Master Security & Data Protection Blueprint

Based on the complete context of our development sessions, global configuration rules, and the specific architecture of the app (Next.js, Supabase, 3D WebGL, macOS Agent integration), here are 100 highly granular security, app safety, user data protection, and anti-hacking instructions.

---

## 1. Next.js & Server-Side Security
1. **Server Actions Isolation**: Always declare `"use server";` at the very top of server action files to prevent accidental leakage of backend code to the client bundle.
2. **Environment Variable Secrecy**: Never prefix sensitive keys (like Supabase Service Role) with `NEXT_PUBLIC_` or `VITE_`.
3. **HTTP-Only Cookies**: Ensure all session cookies generated by `@supabase/ssr` are HTTP-only to prevent Cross-Site Scripting (XSS) extraction.
4. **Secure Cookie Transmission**: Enforce the `Secure` flag on all auth cookies so they are only transmitted over HTTPS.
5. **Strict SameSite Policy**: Set cookie `SameSite` attribute to `Lax` or `Strict` to mitigate Cross-Site Request Forgery (CSRF).
6. **No Client-Side Secrets**: Never hardcode API keys for third-party services in React components.
7. **Error Boundaries**: Always implement a root Error Boundary to catch rendering errors and prevent raw stack traces from leaking to the user.
8. **Suspense Boundary Protection**: Wrap all async 3D assets or data fetches in `<Suspense>` to prevent uncaught promise rejections from crashing the entire DOM.
9. **API Route Parameter Validation**: Validate all incoming `FormData` or JSON payloads before processing them.
10. **Type-Safe Payloads**: Use TypeScript/Zod interfaces to enforce the shape of data received from the client.
11. **Sanitize User Input**: Ensure any user-submitted text is sanitized before rendering it back to the DOM to prevent Stored XSS.
12. **Rate Limiting**: Implement rate limiting on authentication routes to prevent brute-force attacks.
13. **Deployment Security**: Ensure cloud deployment settings do not publicly expose deployment logs or source maps to unauthorized users.
14. **Dynamic Import Safety**: Use dynamic imports for heavy client-side libraries (like 3D rendering) to prevent server-side hydration mismatches and memory leaks.
15. **Content Security Policy (CSP)**: Configure headers to enforce a strict CSP, allowing assets only from trusted domains.
16. **X-Frame-Options**: Set headers to `DENY` or `SAMEORIGIN` to prevent clickjacking attacks on the dashboard.
17. **X-Content-Type-Options**: Set `nosniff` to prevent the browser from MIME-sniffing the responses.
18. **Referrer-Policy**: Set to `strict-origin-when-cross-origin` to protect URL parameters when linking out.
19. **Strict-Transport-Security (HSTS)**: Enforce HSTS so browsers only ever connect via HTTPS.
20. **Avoid `dangerouslySetInnerHTML`**: Never use this React prop unless rendering pre-sanitized, trusted markdown.

## 2. Supabase Authentication & Session Management
21. **JWT Expiration**: Ensure Supabase JWTs have short expiration windows (e.g., 1 hour) relying on secure refresh tokens.
22. **OAuth Callback Security**: Process all OAuth (Google/Apple) callbacks strictly with secure redirect origin (`window.location.origin`) and PKCE exchange to keep the exchange token out of browser history.
23. **Verify Auth State on Server**: Never trust client-side local storage alone for authorization; always verify session tokens on the server or with Supabase auth API.
24. **Multiplayer Workspace Validation**: If checking if a user belongs to a team, do the validation via a server-side DB query, not a local storage variable.
25. **Prevent Session Fixation**: Ensure a new session token is generated upon successful login.
26. **Logout Invalidation**: Ensure the logout function calls `supabase.auth.signOut()` to invalidate the token on the server, rather than just deleting the local cookie.
27. **Password Strength Requirements**: Enforce strong password policies (min length 8, uppercase, lowercase, numbers, special characters).
28. **Email Verification Requirement**: Ensure users verify their email address before granting full access to cloud synchronization.
29. **Magic Link Expiry**: Set short expiration times on magic links to prevent intercepted emails from being used later.
30. **No Sensitive Data in JWT Payload**: Do not store private PII inside public JWT claims.

## 3. Database (PostgreSQL) & Row Level Security (RLS)
31. **Enable RLS on All Tables**: Never leave a Supabase table with RLS disabled.
32. **Default Deny Policy**: Ensure that by default, all operations (SELECT, INSERT, UPDATE, DELETE) are denied unless an explicit policy allows them.
33. **IDOR Prevention (Insert)**: When inserting rows, override any client-provided `user_id` with `auth.uid()`.
34. **IDOR Prevention (Select)**: Create an RLS policy: `CREATE POLICY "Users view own data" ON table FOR SELECT USING (auth.uid() = user_id);`
35. **IDOR Prevention (Update)**: Create an RLS policy forcing the `user_id` to match `auth.uid()` for updates.
36. **IDOR Prevention (Delete)**: Restrict deletion strictly to the row owner.
37. **Parameterized Queries**: Always use Supabase's query builder (which utilizes parameterized queries) to prevent SQL injection.
38. **Never Execute Raw SQL from Client**: Disable the Supabase GraphQL or REST endpoints for executing raw SQL strings.
39. **Secure Database Backups**: Ensure Supabase automated point-in-time recovery (PITR) is enabled.
40. **Data Encryption at Rest**: Rely on Supabase's default AES-256 encryption for all stored table data.
41. **Role-Based Access Control (RBAC) via DB**: Store user roles in a secure `user_roles` table, not in frontend `localStorage`.
42. **Hardcoded Admin Overrides**: For highly sensitive telemetry, explicitly check authorized admin emails on the server before querying.
43. **Soft Deletes**: Consider adding an `is_deleted` boolean flag rather than hard-deleting rows, to allow for recovery and audit trails.
44. **Audit Logging**: Create a database trigger to log sensitive actions into an immutable `audit_logs` table.
45. **Restrict Public Schema Access**: Do not expose sensitive tables to the `anon` role; restrict them entirely to the `authenticated` role.
46. **Limit Data Fetching**: Only `select()` the columns you need rather than `select('*')` to prevent over-fetching sensitive columns.
47. **Restrict Cross-Tenant Joins**: Ensure RLS policies extend to foreign key relationships.
48. **Database Connection Pooling**: Use Supabase PgBouncer/Supavisor to prevent connection exhaustion attacks.
49. **Secure Webhook Secrets**: If using database webhooks to trigger external APIs, secure the webhook endpoints with cryptographic signatures.
50. **Disable Inactive Users**: Automatically suspend or flag users who exhibit anomalous query patterns via database triggers.

## 4. Legal Compliance & Privacy (GDPR/CCPA)
51. **Dedicated Privacy Policy (`/privacy`)**: Maintain a page detailing exact data collection practices.
52. **Terms of Service (`/terms`)**: Maintain a binding legal agreement protecting the app from liability.
53. **Sales & Refunds Policy (`/refunds`)**: Explicitly state non-refundable subscription terms to win chargeback disputes.
54. **Cookie Policy (`/cookies`)**: Detail the types of cookies used (Strictly Necessary vs. Analytics).
55. **Right to Access (GDPR)**: Provide a mechanism for users to export their workspace data.
56. **Right to Erasure (GDPR)**: Provide a mechanism allowing users to delete their account and all associated database rows.
57. **No Sale of Data**: Explicitly guarantee in writing that user PII is not sold to third parties.
58. **AI Data Opt-Out**: Ensure that any third-party AI integrations are configured via API to not use user data for model training.
59. **Age Restriction Compliance**: State in the Terms that users must be 18+ to execute legally binding quotes or transactions.
60. **Data Protection Officer (DPO)**: List a contact email for privacy inquiries.

## 5. UI/UX Safety & Active Consent
61. **Mandatory Form Consent Checkboxes**: Physically block account creation until the user checks "I agree to Terms & Privacy."
62. **OAuth Consent Awareness**: Include text stating that clicking "Continue with Google" constitutes agreement to the legal policies.
63. **Global Cookie Banner**: Implement a banner that blocks non-essential tracking scripts until explicit consent is given.
64. **Granular Cookie Controls**: Allow users to accept or decline non-essential cookies.
65. **Consent Storage**: Save user cookie preferences securely in `localStorage` so it persists across sessions.
66. **Accessible Error Messages**: Do not leak system architecture details in UI error toasts (e.g., say "Failed to process request securely" instead of "Postgres constraint violation on row 45").
67. **Destructive Action Confirmation**: Require users to confirm via a secondary modal before wiping data.
68. **Session Timeout Warnings**: If implementing idle timeouts, warn the user before securely logging them out.
69. **Loading State Disablement**: Disable submit buttons and show loading spinners (`<Loader2>`) during form submissions to prevent accidental double submissions.
70. **Phishing Prevention**: Ensure all platform emails originate from verified domains using strict DMARC/DKIM records.

## 6. JARVIS / System Agent Operational Security
71. **Cloud-Only Storage Discipline**: The AI must never create organizational folders in the local macOS Finder; all project structures must remain in Google Drive ("AG Project").
72. **"Burn After Reading" Sent Files**: The AI must automatically back up any sent files to `AG Project/Sent Backups`.
73. **Local File Eradication**: Immediately after backing up sent files, the AI must permanently delete the local macOS copies to prevent local data leakage.
74. **Contact Anti-Spoofing**: When using Mac Messages or AppleScript, the AI is strictly forbidden from creating new contacts.
75. **Contact Verification**: The AI must actively verify the recipient against existing saved contacts before dispatching payloads.
76. **Persona Integrity Verification**: The AI must operate strictly under the "JARVIS" persona, acting politely and proactively.
77. **Authorization Confirmation**: The AI must address the authorized user specifically as "Mohammed Sir" to acknowledge the chain of command.
78. **Proactive Analytics Monitoring**: The AI must be ready to autonomously scan system logs and build outputs for vulnerabilities or performance degradation when requested.
79. **Execution Halting on Ambiguity**: The AI must stop and ask for clarification rather than making destructive changes to the codebase if intent is unclear.
80. **Tool Constraint Adherence**: The AI must prioritize specific, safe tools (like `replace_file_content` or `grep`) over risky, broad shell commands whenever possible.

---

## 7. 3D, WebGL, & Asset Security
81. **Localize 3D Assets**: Remove external HDRI network dependencies to prevent CORS crashes or network blocking by corporate firewalls.
82. **Procedural Environment Fallbacks**: Use mathematical/procedural lighting instead of relying on external image downloads for 3D reflections.
83. **Memory Leak Prevention in Canvas**: Ensure all 3D canvas components properly dispose of geometry, materials, and textures when unmounted.
84. **Sync Tickers Safely**: When syncing external scroll libraries (Lenis) with GSAP/RAF, ensure the `requestAnimationFrame` ticker is properly cleaned up in the `useEffect` return function to prevent infinite loop crashes.
85. **Isolate Third-Party Scripts**: Load third-party scripts with deferred/afterInteractive strategies to prioritize core app execution and prevent script hijacking.
86. **Asset Compression**: Compress 3D models using Draco or procedural geometry to prevent bandwidth exhaustion attacks.
87. **Frame Rate Throttling**: Configure the 3D Canvas to stop rendering or lower its framerate when the user switches tabs (`document.hidden`), preserving user battery and preventing CPU hijacking.
88. **Sanitize Image Uploads**: Strictly validate MIME types and strip EXIF data before storing in Supabase Storage.
89. **Enforce Storage Size Limits**: Restrict file upload sizes to prevent storage denial-of-service (DoS) attacks.
90. **Public vs. Private Buckets**: Ensure user-uploaded documents are stored in private Supabase buckets requiring signed URLs to access.

---

## 8. Ecosystem & Dependency Hardening
91. **Dependency Pinning**: Ensure package.json dependencies are pinned to specific versions to prevent supply-chain attacks from malicious minor updates.
92. **Audit Node Modules**: Regularly run `npm audit` and fix high-severity vulnerabilities in the build pipeline.
93. **Remove Unused Code**: Aggressively prune unused packages to reduce the application's attack surface.
94. **Protect the `.env` File**: Never commit `.env` or `.env.local` to GitHub. Add them to `.gitignore`.
95. **Rotate Secrets**: Regularly rotate the Supabase JWT secret and database passwords.
96. **Git Branch Protection**: Enforce branch protection rules on `main` requiring reviews or passing CI/CD checks before merging.
97. **Vercel/Hosting Env Validation**: Ensure production environment variables are correctly mapped and do not contain development keys.
98. **Disable Source Maps in Prod**: Ensure proprietary logic isn't easily readable by attackers in production bundles.
99. **MCP Server Authorization**: When adding third-party MCP servers, explicitly verify the permissions requested to grant only the minimum necessary privileges.
100. **Continuous Security Audits**: Periodically prompt the AI to run security and accessibility audits on new code commits.
